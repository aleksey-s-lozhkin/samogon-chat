# Память проекта «Самогон»

Короткий контекст для новой задачи: сначала прочитайте этот файл, затем только
затронутые разделы документации и кода. Не перечитывайте весь ТЗ или старые
диалоги без конкретной причины. Факты о Git и production всегда проверяйте
заново; секреты и пользовательские данные сюда не записываются.

## Что это за приложение

«Самогон» — веб-чат для разработчиков. Сервер написан на Django; Channels и
WebSocket доставляют сообщения, PostgreSQL хранит данные, Redis поддерживает
соединения и фоновые задачи, Celery выполняет отложенную работу. Веб-интерфейс
использует серверные шаблоны, HTMX и JavaScript. Семён — локальный ИИ-бармен
через Ollama. Есть версионированный HTTP API для мобильного клиента.

Основные каталоги: `chat/` — комнаты, сообщения, заметки, WebSocket и Семён;
`users/` — аккаунты, профиль и Push; `config/` — настройки и маршруты;
`static/` и `templates/` — интерфейс; `deployment/` — развёртывание.

## Принятые решения

- Открытая регистрация управляется `REGISTRATION_OPEN`; изменение переменной
  требует пересоздания контейнеров штатным deploy. Проверка email при
  регистрации пока не вводилась. Регистрация требует галочку 18+ и согласия
  с правилами; дата и версия принятой редакции сохраняются в аккаунте.
- `DEBUG` по умолчанию `0`, а `SECRET_KEY` и `DATABASE_URL` обязательны вне
  DEBUG. Локально значения берутся из `.env`, который читается автоматически.
  Тесты и браузерный smoke сохраняют режим разработки через `manage.py test`.
- Состояние присутствия разделено: `online_users` — онлайн конкретной беседы,
  `user_presence` — глобальный справочник для свёрнутого списка «Отошли».
- Вложения-документы всегда скачиваются, а не открываются внутри origin.
  Расширение `.js` не принимается: раньше inline-выдача давала stored XSS.
- В закрытой беседе ограничения на число приглашённых нет: действует только
  «минимум один участник». Раньше форма требовала одного-двух, из-за чего
  беседа с большим составом вообще не сохранялась.
- Свой текстовый статус меняется в профиле. В панели гостей остался только
  быстрый выбор из справочника: инлайновое поле было тесным и вызывало
  автоматический зум Safari на телефоне.
- Изображения вложений открываются в общем модальном окне (чат и личные
  заметки) с кнопкой сохранения. Ссылка остаётся запасным путём без JavaScript.
- Браузерный smoke использует временный `MEDIA_ROOT`, поэтому тестовые вложения
  больше не попадают в рабочий каталог `media/`.
- Смена статуса с HTTP-страницы профиля рассылает снимок присутствия по
  WebSocket: иначе другие гости видели прежний статус до перезагрузки.
  Снимок «до» берётся до `form.is_valid()` — валидация уже подменяет поля
  instance данными формы.
- Палитра реакций и набор emoji в composer расширены; допустимые реакции API
  берёт из модели `MessageReaction.Emoji`, чтобы список не расходился.
- Кнопка «Войти в бар» на главной ведёт гостя на страницу входа с возвратом
  в `/chat/`, а не сразу в список комнат.
- Изображения хранятся в двух разрешениях: оригинал и превью до 640 px по
  длинной стороне. Лента грузит превью, просмотр и скачивание — оригинал.
  Превью не создаётся, если после перекодирования оно выходит не меньше
  оригинала: иначе мелкая картинка стала бы тяжелее.
- Птица-Говорун отложена до отдельного решения. Согласованы рамки: только одна
  комната на обкатку, выключено по умолчанию, курируемый список поводов вместо
  RSS, тихие часы по одному эталонному поясу (комната общая — «ночь для всех»
  определить нельзя), ботов и суперпользователей не считаем гостями.
  Подробности и обоснования — в `docs/product-specification.md`.
- Проверка языка ответа бармена вынесена в `chat/services/language.py` без
  зависимостей от Django: раньше она была скопирована в трёх местах и
  расходилась. Пунктуация CJK теперь тоже считается иероглифами.
- Текущая страница чата подгружает старые сообщения по мере прокрутки. Личные
  заметки доступны только владельцу; поиск по ним работает в браузере, без
  отправки поискового запроса на сервер.
- При отказе WebSocket из-за истёкшего входа интерфейс предлагает войти снова
  с возвратом в ту же комнату. Один лишь код `403` в журнале Nginx не доказывает
  причину отказа: нужны состояние сессии и серверные признаки авторизации.
- Семён должен отвечать коротко, естественно, по-русски и в образе бармена.
  Изменения его поведения проверяются на реальной модели наряду с тестами.
- Production-данные, ключи, cookie и закрытые адреса не копируются в репозиторий
  или публичные отчёты. Внешние уведомления не содержат текст сообщений.
- Старые образы на сервере чистит сам пайплайн: перед загрузкой он удаляет все
  теги Самогона, кроме `latest` и `rollback`, и держит ровно два образа —
  текущий и предыдущий для автоматического отката. Вручную удалять `rollback`
  нельзя: именно им пайплайн откатывается, если новая версия не поднялась.
  Растёт не диск сервера, а реестр — там тег на каждый коммит.
- Web Push уходит через Celery. Раньше общая рассылка из админки выполнялась
  прямо в запросе и ждала push-службу, а личное уведомление жило фоновой
  задачей внутри веб-процесса и терялось при перезапуске. Если брокер
  недоступен, отправка падает обратно в текущий процесс — лучше задержка, чем
  молча потерянное уведомление.
- Логирование: `django.request` на уровне ERROR (5xx без шума 404/403) и
  `django.security` на WARNING. Уровни настраиваются окружением.
- Добавлены индексы под постоянные запросы: история комнаты, личные сообщения и
  очередь нерассмотренных жалоб.

## Быстрый маршрут

1. Проверьте `git status --short --branch` и свежие `origin/develop` и
   `origin/main`. Старый SHA не подтверждает текущий deploy.
2. Найдите нужный код через `rg`, откройте только релевантные файлы. Для границ
   задачи обращайтесь к [ТЗ](docs/product-specification.md), для потоков данных —
   к [архитектуре](docs/architecture.md). [Статус релиза](docs/release-status.md)
   датирован 26.09.2026 и не является актуальным списком блокеров.
3. Для одной задачи создайте отдельную ветку от свежего `develop`. После merge
   не продолжайте работу в старой feature-ветке.
4. Сначала запустите узкие тесты. Браузерный smoke нужен при изменении UI;
   полный набор выполняет CI. Не повторяйте успешно пройденные длительные
   проверки без нового изменения или диагностической гипотезы.
5. В отчёте различайте «проверено локально», «слито в `develop`» и
   «доставлено в production».

Команды — в [cloud.md](cloud.md) и [документации по тестированию](docs/testing.md).
Production-проверка — в [release checklist](docs/release-checklist.md). Этот
файл не назначает приоритет задачам из ТЗ.
