# Архитектура

«Самогон» — модульное Django-приложение. Серверные HTML-страницы и HTTP API
используют одну предметную модель и одни сервисы; отдельного приложения с
дублирующей API-логикой нет.

## Границы приложений

- `chat` владеет комнатами, сообщениями, вложениями, реакциями, ответами,
  заметками, жалобами и WebSocket-протоколом.
- `users` владеет аккаунтами, профилем, OAuth, блокировками и Web Push.
- `config` собирает настройки и корневые маршруты, а также публикует OpenAPI.

Внутри предметного приложения интерфейсы разделяются пакетами. Например,
`users/views.py` обслуживает Web, а `users/api/` содержит JSON views,
serializers и URL. Оба слоя вызывают сервисы из `users/services/`.

## Поток сообщения

1. `ChatConsumer` проверяет сессию, доступ к комнате и ограничение частоты.
2. Валидатор проверяет входное событие.
3. `MessageService` применяет правила видимости и сохраняет сообщение.
4. Channels рассылает безопасное событие разрешённым получателям.
5. Для личной реплики Web Push запускается без текста и имени отправителя.

PostgreSQL является источником истины. Redis используется для Channels,
ограничений частоты и присутствия, но потеря Redis не должна удалять данные.

## Web и API

Web-страницы остаются серверными Django Templates с HTMX и JavaScript. REST API
версионируется под `/api/v1/`; корневой `config/urls.py` только подключает API
предметных приложений. Новые API-операции должны вызывать существующий сервис,
а не переносить бизнес-правило в serializer или view.

OpenAPI описывает только HTTP. События Channels документируются отдельно в
[WebSocket-протоколе](websocket-protocol.md).

## Безопасность данных

- личная реплика возвращается только её участникам;
- файлы выдаются после повторной проверки доступа;
- API устройств возвращает непрозрачный `device_id`, но не endpoint и ключи;
- OAuth-токены не сохраняются;
- документация и примеры не содержат production-адреса и секреты.

## Следующая декомпозиция

По мере роста API аналогичные пакеты `api/` добавляются внутрь `chat` и других
приложений. `ChatConsumer` можно разделить на фабрику событий, разрешение
получателей и рассылку. Это следует делать отдельными небольшими изменениями с
сохранением протокола, а не общей перестройкой перед релизом.
