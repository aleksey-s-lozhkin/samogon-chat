# Статус открытой беты на 26.09.2026

Этот документ отделяет подтверждённые production-проверки от оставшейся
приёмки. Подробные требования — в [ТЗ](product-specification.md), команды для
нового образа — в [release checklist](release-checklist.md). Результат проверки
старого образа не подтверждает автоматически текущий deploy: точный образ и
состояние Git перед выпуском проверяются заново.

## Подтверждено владельцем проекта

- 18 сентября проверены одинаковый образ web и worker, готовность PostgreSQL и
  Redis, liveness/readiness, отсутствие рестартов и OOM.
- Резервная копия PostgreSQL и media успешно восстановлена в изолированном
  контейнере, скопирована за пределы production-хоста; контрольные суммы
  совпали. Перед последующей очисткой тестовых данных создана и проверена
  отдельная копия.
- Аудит 30 активных + 30 неактивных клиентов завершился `status: ok`,
  `errors: []`, кодом 0. После него web и worker оставались healthy без
  рестартов и OOM, readiness возвращала `ok`. Отдельно успешно проверены три
  ответа Семёна и публичный production smoke.
- Временная audit-комната, 60 аккаунтов и их сессии удалены; наличие комнаты,
  аккаунтов и файлов сессий повторно проверено. После очистки тестовых данных
  сохранены три согласованных аккаунта, пять публичных бесед и аватары;
  сообщения, заметки и 40 связанных файлов удалены. Возникший после запуска
  web/worker ответ 502 устранился после перезагрузки Nginx; readiness снова
  вернула `ok`.
- Открытая регистрация без приглашения и вход проверены владельцем; задача
  регистрации принята как выполненная. Для последующих образов подтверждены публичный smoke, готовность сервисов и
  отсутствие ошибок в проверенных журналах. GitHub/Google OAuth, Turnstile и
  добровольный Web Push проходили production-проверку ранее.
- Реализованы поиск сообщений и личных заметок, подгрузка старой истории,
  вложения, аудио, реакции, ответы, жалобы, закрытые беседы и восстановление
  входа после отказа WebSocket. Поиск заметок и последние улучшения composer
  опубликованы; проверка их работы на реальных устройствах продолжается.

## Выпуск админки и модерации

Подготовлены строгая серая тема админки, русские подписи и отдельная страница
`/moderation/` внутри PWA. Жалобы группируются по сообщениям, решения сохраняют
причину и журнал; админка использует тот же сервис. Исправлена потеря записей
журнала при скрытии/восстановлении через действия админки.

Локально прошли полный серверный прогон (304 теста), после финальных правок —
109 адресных тестов и отдельный smoke desktop/mobile Chromium и mobile WebKit.
Проверены также формы сообщения, push-рассылки, выгрузки и диагностики.
При подготовке [PR #217](https://github.com/aleksey-s-lozhkin/samogon-chat/pull/217)
исправлено смещение текста при объединении подгруженной истории в группу;
общий browser smoke прошёл desktop Chromium, mobile Chromium и WebKit.

Выпуск выполняется через `develop` → `main`: штатный deploy применяет
миграции `chat` и `users` и обновляет static. Фактический результат публикации
проверяется в [Publish and deploy](https://github.com/aleksey-s-lozhkin/samogon-chat/actions/workflows/publish-deploy.yml)
и публичным production smoke. Приёмка на реальных устройствах и проверка
одновременных решений на PostgreSQL остаются отдельными шагами после deploy.
Подробности: [администрирование и модерация](moderation.md).

## Локальный пакет: вложения, ввод, статусы и Семён

Подготовлены прозрачный фон вложений, короткие подсказки с корректной высотой
поля, справочник статусов в админке и карточка Семёна в правой панели «Гости».
Для выпуска нужны миграция `users.0010` и обновление static. Текущие статусы
пользователей сохраняются. Действия с Семёном используют прежние режимы
общего и личного обращения, без самостоятельных новых реплик.

Полный локальный серверный прогон: 315 тестов успешно; Django checks и
проверка отсутствия новых миграций прошли.

Автоматические браузерные сценарии обновлены для новой навигации и проверки
размеров подсказки. Локально браузеры не запускались по указанию владельца;
визуальная приёмка и проверка телефонов остаются после его PR/CI и deploy.
Синхронизацию репозитория, PR, слияния и публикацию выполняет владелец.

## Остаётся подтвердить на текущем образе

   затронутых сценариев по [чек-листу](release-checklist.md), включая журналы,

2. Провести отдельную проверку доступности форм и восстановления доступа с
   VoiceOver. Проверить composer и запись/воспроизведение аудио на iPhone и
   Android PWA. Принятую регистрацию повторно не открывать без нового дефекта.
3. Проверить значок уже установленной PWA на реальном устройстве; при
   необходимости переустановить PWA, поскольку обновление системной иконки
   может отставать от обновления страницы. Собрать замечания реальных
   пользователей по [сценарию приёмки](ui-beta-review.md).

## Этап интерфейса: даты и гости

Локально подготовлены стопка дат глубиной до трёх слоёв, раскрываемый список
дат загруженной истории, вложения и даты без рамок, Семён внутри онлайн-блока
и одинаковые действия с гостями. Этот этап не требует миграций БД и может
выпускаться независимо от мобильного API после CI. Коммит:
`Refine date navigation and unify guest actions`. PR в develop:
`Improve date navigation, attachments and guest menus`. Выпускной PR в main:
`Release chat date navigation and guest menus`. PR и deploy выполняет владелец.
