# Качество Семёна

## Текущее состояние

Семён отвечает через локальный Ollama API в отдельной Celery-задаче. В модель
передаются системный промпт, текущая реплика и до восьми предшествующих
видимых сообщений из той же открытой беседы. Личные, скрытые и закрытые сообщения
не попадают в контекст. Логины, имена комнат и другие идентификаторы заменяются
нейтральными `guest_1`, `guest_2` и `semen`.

Медицинский риск, запрос секретов, разрушительные действия, раскрытие внутренних
инструкций, грубая самооценка и прямые оскорбления обрабатываются предсказуемыми
защитными ответами до вызова модели.

Технические production-логи намеренно не содержат тексты сообщений. В них
остаются модель, длительность запроса и факт повторной генерации из-за языка.
Тексты для исследования берутся из связанных `BartenderJob` и `Message` только
явной локальной командой.

## Безопасная выборка

Метрики последних успешных публичных обращений без содержимого:

```bash
python manage.py export_bartender_audit --limit 100
```

Псевдонимизированные тексты и до шести предшествующих публичных реплик:

```bash
python manage.py export_bartender_audit \
  --limit 100 \
  --context-size 6 \
  --include-content > bartender-audit.jsonl
```

Личные обращения к Семёну и закрытые беседы команда не экспортирует. Она
заменяет очевидные email, IP-адреса, URL и упоминания, однако свободный текст
невозможно надёжно анонимизировать автоматически. Поэтому файл с содержимым:

- считается чувствительным;
- не добавляется в Git и не отправляется в обычные логи;
- хранится только на защищённой рабочей машине;
- удаляется после анализа.

Поле `context_sent_to_model` равно `null`: точный исторический объём контекста пока не
сохраняется в `BartenderJob`, поэтому аудит не выдаёт текущую политику за факт о старом
ответе.

`configured_model_at_export` показывает текущую настройку во время экспорта, а
не гарантированно модель исторического ответа: версия модели пока не сохранялась
в `BartenderJob`.

## Порядок улучшения

1. Разметить реальные ответы: потеря контекста, повтор, выдуманный факт,
   неуместное вмешательство, плохая диагностика, тон и длина.
2. Собрать небольшой стабильный набор обезличенных сценариев.
3. Прогнать одинаковые сценарии через доступные модели и измерить качество,
   задержку и использование памяти.
4. Добавить ограниченный контекст с обязательной фильтрацией личных и скрытых
   сообщений.
5. Повторить сравнение и только после него выбрать модель и параметры.
6. Отдельно внедрить проверяемую генерацию коротких атмосферных строк; точные
   цитаты PEP брать только из подготовленного каталога со ссылками.

Изменение модели в production выполняется переменной `OLLAMA_MODEL`. Содержимое
диалогов не должно добавляться в постоянное логирование даже на время настройки.

## Сравнение моделей

В `deployment/ollama/benchmark-dialogues.json` хранится синтетический набор,
повторяющий обнаруженные классы проблем без копирования реальных разговоров.
Скрипт запускает каждый сценарий в двух режимах:

- `last` — модель получает только последнюю реплику, это контрольный режим;
- `context` — модель получает короткую историю с обозначением участников.

Запуск на машине с доступом к Ollama:

```bash
python deployment/ollama/benchmark_dialogues.py \
  --url http://<ollama-host>:11434 \
  --mode context \
  --runs 3 \
  --output benchmark-results.jsonl \
  qwen3:8b

python deployment/ollama/benchmark_evaluate.py benchmark-results.jsonl
```

Одна строка результата содержит сценарий, модель, режим, ответ, полную задержку,
время загрузки и количество токенов. Файл результатов не содержит production-
переписку, но перед публикацией его всё равно следует просмотреть.

Модели сравниваются при одинаковых `temperature`, `num_ctx` и `num_predict`.
Каждая модель проходит все сценарии подряд, чтобы постоянное переключение весов
не искажало задержку и не создавало лишнюю нагрузку на Ollama.
Сначала оцениваются соответствие сценарию, отсутствие выдумок, естественность и
тон, а затем скорость и потребление памяти. Более быстрая модель не выбирается,
если она регулярно теряет контекст или нарушает границы роли.

### Проверка характера

Текущий production-промпт хранится в `chat/services/prompts/semen.txt` и по умолчанию
используется бенчмарком. Для чистого теста модели без защитного слоя есть флаг
`--without-guardrails`; обычный финальный прогон должен оставаться максимально близким к приложению.

Контрольный прогон 12 сентября 2026 года: Qwen 3 8B, 20 сценариев по три повтора,
ограниченный контекст и защитный слой. Все 60 ответов прошли машинные стоп-факторы;
среднее время с учётом мгновенных защитных ответов — 496 мс, среднее время вызова самой модели — 661 мс. Ручной просмотр остаётся
обязательным: машинная оценка не определяет, смешна ли шутка и достаточно ли тепло звучит ответ.
