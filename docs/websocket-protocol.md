# WebSocket-протокол

Соединение комнаты открывается по `/ws/chat/<room-slug>/`. Требуются действующая
Django-сессия и доступ к комнате.

## Коды закрытия

- `4401` — пользователь не авторизован;
- `4403` — аккаунт ограничен или комната недоступна;
- `4404` — комната не найдена.

## События сервера

- `history` — доступная история комнаты;
- `message` — новая реплика;
- `reaction_update` — новое состояние одной реакции;
- `typing_update` — краткоживущий индикатор набора;
- `online_users` — пользователи онлайн в комнате;
- `user_presence` — безопасные публичные данные списка гостей;
- `attachment_update` — вложения сообщения после загрузки;
- `message_deleted` — скрытие реплики;
- `error` — безопасная пользовательская ошибка.

Событие сообщения может содержать адресата, признак приватности, безопасную
цитату, цвет, реакции и защищённые ссылки на вложения. Сервер фильтрует историю
и события отдельно для каждого пользователя; личный текст не рассылается
посторонним.

## События клиента

- отправка сообщения с необязательными `recipient`, `reply_to` и режимом Семёна;
- `reaction` с ID сообщения и разрешённым emoji;
- `typing` с текущим адресатом;
- `presence_status` с кодом доступного статуса из справочника админки
  (пустая строка сбрасывает статус; неизвестные и отключённые коды отклоняются);
- `presence_ping` — служебный heartbeat активного соединения.

Клиент отправляет `presence_ping` раз в 25 секунд. Сервер продлевает lease
соединения; по умолчанию запись исчезает через 75 секунд без heartbeat. Поэтому
закрытие приложения, обрыв сети или аварийное завершение браузера не оставляют
пользователя онлайн навсегда. В Redis используются отдельные ключи presence v2,
старые записи предыдущего формата не влияют на список гостей.

Если владелец закрытой беседы исключает участника, удаляет беседу или
приглашённый участник выходит сам, сервер отправляет внутреннее событие
`room_access_revoked` и закрывает его активное соединение кодом `4403`.

Сервер повторно проверяет типы, длину, доступ, допустимые emoji и ограничения
частоты. Клиентская валидация не считается границей безопасности.

## Персональная блокировка

После изменения персональной блокировки сервер заново присылает `history`
(заменить текущую историю), затем `unread_snapshot` и обычный `user_presence`.
Формат `user_presence` не меняется; недоступные и лично заблокированные аккаунты
из `users` и `online` исключаются. `unread_snapshot` имеет вид
`{"type":"unread_snapshot","rooms":{"general":{"general":false,"personal":true}}}`.
Клиент заменяет прежние индикаторы непрочитанного целиком. Неизвестные события
старые клиенты могут игнорировать; PWA обновлена для обработки снимка.

Новые личные сообщения заблокированной пары отклоняются событием `error`.
Сообщения, реакции, вложения и индикаторы набора проверяются также непосредственно
при доставке, чтобы поставленное в очередь событие не обошло новую блокировку.
