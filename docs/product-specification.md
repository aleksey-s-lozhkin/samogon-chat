# Техническое задание и roadmap «Самогона»

Этот документ фиксирует согласованные продуктовые требования. Галочка означает,
что возможность принята и запланирована, но не обязательно уже реализована.

## Следующий этап: живой чат

### Базовая безопасность открытой беты

- [x] **Модерация в админке.** Группа `Moderators` создаётся после миграций;
  назначение выполняет суперпользователь. Модератор скрывает сообщения и видит
  журнал решений, но не получает superuser-права.
- [x] **Временные и постоянные баны.** Причина, срок и автор решения сохраняются
  в журнале. Заблокированный пользователь не входит в HTTP- или WebSocket-чат.
- [x] **Cloudflare Turnstile.** Интеграция реализована и проверяет токен на
  сервере. Для включения в production остаётся добавить ключи виджета.

### Идентичность пользователей

- [ ] **Аватары в интерфейсе.** Рядом с ником в сообщениях, карточках
  пользователей и личных диалогах показывается круглый аватар размером,
  подходящим для места отображения. Если пользователь не загрузил файл,
  используется круг с инициалом.
- [ ] **Тёплый приём новичка.** При первом входе пользователь получает одно
  приветственное сообщение Семёна с подсказкой о комнатах, личных сообщениях и
  приглашении к разговору. Повторный вход не создаёт дубликат.
- [ ] **«Стаканов налито».** В профиле и карточке пользователя вместо сухого
  счётчика сообщений показывается число отправленных сообщений с барной
  формулировкой. Метрика должна быть понятна и не имитировать рейтинг.

### Бармен и атмосфера

- [ ] **Анимированный Семён.** На карточке бармена используется небольшая
  оптимизированная GIF/WebP-анимация: рисованный NPC, протирающий стакан, или
  дружелюбный робот. Анимация не должна мешать чтению; для
  `prefers-reduced-motion` показывается статичный кадр.
- [ ] **Фоновый шум бара.** В настройках доступен добровольный переключатель.
  По умолчанию звук выключен, запуск происходит только после явного действия
  пользователя, громкость регулируется и сохраняется в профиле/браузере.
  Нужен звук с корректной лицензией.

### Сообщения и вложения

- [ ] **Файлы и изображения.** Пользователь может прикреплять файлы и картинки
  к сообщению. Изображения получают миниатюру и полноразмерный просмотр,
  ссылки — безопасный предпросмотр по allowlist и таймауту.
  Выбор до трёх файлов, локальный предпросмотр и показ вложений в ленте
  реализованы. Безопасный предпросмотр внешних ссылок остаётся отдельной
  задачей: он не должен запрашивать произвольные адреса с сервера.
- [ ] **Безопасность вложений.** Разрешённые типы, лимит размера, случайные
  имена файлов, отдельное хранилище, запрет исполнения и проверка содержимого
  обязательны до открытой регистрации. Вложения не должны быть доступны через
  предсказуемый путь до проверки прав доступа.
  Серверная основа реализована: JPEG/PNG/WebP до 5 МБ, PDF и UTF-8 документы
  из allowlist до 2 МБ, не больше трёх файлов на сообщение. Файлы получают
  UUID-имя и в production выдаются Nginx только после проверки Django. UI
  загрузки, миниатюры и просмотр остаются следующим этапом.
- [ ] **Смайлики на десктопе.** Добавляется компактный emoji picker; с мобильных
  устройств остаётся системная клавиатура. Последние и популярные emoji
  показываются первыми.
- [ ] **Автозамена смайликов.** На отправке заменяются только популярные
  сочетания: `:)` → `😊`, `;)` → `😉`, `:D` → `😄`, `:(` → `😔`, `<3` → `❤️`.
  Замена не выполняется внутри кода и ссылок.
- [ ] **Реакции.** У сообщения можно поставить или снять одну из ограниченного
  набора реакций. Отображаются счётчик и список поставивших; повторное нажатие
  снимает реакцию.
- [ ] **Код в сообщениях.** Блоки между тройными обратными кавычками и строки,
  начинающиеся с `>>>`, отображаются моноширинным блоком. Подсветка синтаксиса
  добавляется только через безопасный санитайзер, без выполнения HTML/JS.

### Навигация и комфорт

- [ ] **Поиск по сообщениям.** Поиск работает только в комнатах и личных
  диалогах, к которым есть доступ. Результат показывает фрагмент, автора, дату
  и ведёт к исходному сообщению. Личные сообщения не должны попадать в чужую
  выдачу или общие индексы.
- [ ] **Скелетоны загрузки.** Пока история комнаты загружается, показываются
  нейтральные серые карточки вместо пустого пространства.
- [ ] **Индикатор «печатает».** WebSocket сообщает о наборе текста с debounce и
  коротким TTL; индикатор видят только участники той же комнаты/личного
  диалога.
- [ ] **Плавный переход к новым сообщениям.** Если пользователь находится
  внизу ленты, новые сообщения мягко прокручивают её вниз. Если он читает
  историю выше, автопрокрутки нет — показывается кнопка новых сообщений.
- [ ] **Подсветка сообщения.** При наведении появляется слабое янтарное
  свечение без ухудшения контраста и без навязчивой анимации.

## Производительность и данные

- [ ] **Последние 50 сообщений в Redis.** Redis используется как быстрый кэш
  истории комнаты для восстановления после перезагрузки. PostgreSQL остаётся
  единственным источником истины; при промахе кэша история читается из БД,
  после записи нового сообщения кэш обновляется или инвалидируется.
- [ ] **Профили в Redis.** Кэшируются только безопасные публичные поля профиля:
  имя, URL аватара, цвет сообщений и счётчик «стаканов». Пароли, email,
  права доступа и авторизация всегда проверяются в БД/Django. Нужны TTL и
  инвалидация при изменении профиля.

## Критерии готовности этапа

1. Все новые возможности работают в общем чате, личных сообщениях и тайном
   столике там, где это уместно.
2. Интерфейс остаётся удобным на мобильном и десктопе.
3. Новые WebSocket-события имеют защиту от спама и покрыты тестами.
4. Вложения, предпросмотр ссылок и поиск проходят отдельную проверку прав
   доступа и безопасности до включения в открытой бете.
5. Redis — ускоритель, а не источник истины: перезапуск Redis не приводит к
   потере сообщений, профилей или прав доступа.
